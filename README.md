# Research Agent Skills

一套可组合的科研工作流技能，覆盖：

```text
研究想法 → 实验验证 → 论文写作
```

仓库中的三个技能可以独立使用，也可以通过 `research_state/`（研究状态目录）和共享数据协议组成完整闭环。

## 为什么要做这个项目？

这个项目的初衷不是把每个人都训练成高产论文作者，而是把论文生产中最消耗精力、最容易被环境阻塞的部分交给 AI托管，让研究者把时间放回找实习、找工作或自己真正想推进的方向。

对于不想把大量时间花在读论文、组织实验和反复写作上的人，或者处在指导不稳定、资源有限、组内难以持续产出论文的环境中的人，论文往往更像一个带有不确定性的研究抽卡过程：

```text
提出一个有潜力的 idea
  → 用最低成本验证
  → 根据结果决定继续、修改、暂停或放弃
  → 将真实证据整理成论文
```

这里的“抽卡”不是放弃科学标准，而是承认论文结果受到想法质量、实验资源、时间、审稿偏好和偶然性的共同影响。这个项目试图把不可避免的不确定性变成可记录、可比较、可复盘的流程。

它尤其适合：

- 想专注实习或工程工作，只希望用较少精力维持一条可靠研究线的人；
- 缺少稳定导师指导，需要自己完成问题定义、实验验证和论文组织的人；
- 不想每次从零开始读大量论文，希望 AI 先完成领域扫描和候选 idea 筛选的人；
- 愿意把自己的研究判断、领域经验和失败经验加入系统的人。

这个项目不会制造论文、伪造创新或包装不存在的实验结果。它的目标是减少重复劳动，而不是降低证据要求。

## 技能

| 技能 | 负责内容 | 可独立使用 |
|---|---|---|
| `research-idea-lab` | 文献检索、创新性分析、想法生成、结构化辩论和实验入口 | 是 |
| `research-experiment-lab` | 实验设计、运行、调试、统计、验证和失败分析 | 是 |
| `ai-research-writing-skill` | 论文故事、论断—证据、章节、引用、图表和投稿检查 | 是 |

论文绘图不包含在本仓库中，请使用独立仓库 [paper-figures-skill](https://github.com/threeing3/paper-figures-skill)。

## Idea Skill 的量化逻辑

`research-idea-lab`（研究想法技能）不是简单给 idea 打“好/坏”标签，也不是预测论文一定能接收。它先经过硬门槛，再进行多维评分。

### 1. 先过致命门槛

以下任一问题为 `fail`（失败）或 `unresolved`（未解决），idea 就不能进入 `experiment-ready`（可实验状态）：

- 核心贡献已经被近似工作完整占据；
- 没有实验能够区分声称的机制和数据、算力、模型规模或提示词差异；
- 一个明显的简单基线或公平计算预算基线就能消除收益；
- 所需数据、算力或评估条件不可获得；
- 核心结论依赖数据泄漏、无效测量或不合适的数据使用；
- 贡献类型与准备声称的论文结论不匹配。

### 2. 再评估 11 个维度

每个维度使用 0–4 分，并附带证据和置信度。总分不是概率，也不是录用率预测。

| 维度 | 关注的问题 |
|---|---|
| 问题重要性 | 问题是否真实且有影响？ |
| 问题半衰期 | 项目完成前问题是否仍然存在？ |
| 机制清晰度 | 是否说明了为什么会有效？ |
| 新颖性证据 | 检索是否充分，差异是否清楚？ |
| 抗碰撞性 | 明天出现近似论文后，是否仍有独立价值？ |
| 科学可靠性 | 假设是否自洽且可证伪？ |
| 兴奋度/意义 | 如果成立，是否带来能力、理解或实践变化？ |
| 可测试性 | 是否存在低成本的区分性验证？ |
| 评估完整性 | 是否有直接指标、强基线、泛化和失败分析？ |
| 可行性 | 数据、算力、时间和工程条件是否允许？ |
| 失败后的剩余价值 | 失败后是否仍能留下方法、资源或分析？ |

其中 `soundness`（科学可靠性）和 `excitement`（研究意义）必须分开记录：一个 idea 可能可靠但不重要，也可能很吸引人但无法验证。

### 3. 用信息增益选择实验

系统不优先选择最复杂或最容易跑出好数字的实验，而是选择单位时间和算力下最能区分竞争性解释的 pilot（先导实验）：

- 如果机制成立，会看到什么？
- 如果只是模型变大、数据变多或提示词更好，会看到什么？
- 哪个最小实验能把这些解释区分开？
- 每种结果会让 idea 继续、修改、暂停还是放弃？

量化结果服务于实验决策，不制造虚假的精确感。

### 4. 强制检查“背景—动机—方法”链条

一个 idea 要进入实验阶段，不能只有一个漂亮的方法名称。必须先写清楚：

```text
背景：现实中存在什么问题？
  ↓
动机：现有方法在哪个具体场景失败，为什么需要改变？
  ↓
方法：提出的机制如何直接解决这个失败，如何被实验证伪？
```

分别给背景扎实度、动机必要性、方法对齐度和方法新颖性打 0–4 分，再给三条连接打分：`背景→动机`、`动机→方法`、`方法→评估`。

```text
base = 0.20*背景 + 0.25*动机 + 0.25*方法对齐 + 0.15*方法新颖性 + 0.15*评估匹配
coherence = min(背景→动机, 动机→方法, 方法→评估)
idea_readiness = 0.70*base + 0.30*coherence
```

任何分项或连接低于 2 分，都不能进入 `experiment-ready`（可实验状态）；总指数低于 2.5 只能继续做检索和框架澄清；2.5–3.2 可以做有明确停止条件的 pilot（先导实验）；达到 3.2 且所有链条至少为 3 分、致命门槛通过后，才允许进入用户选择的实验设计。

这个公式故意保留最低连接分：方法再漂亮，也不能弥补虚构的背景；动机再强，也不能弥补方法与评估不匹配。

## Idea Skill 的产出逻辑

Idea Skill 的产出不是一串未经筛选的灵感，而是逐步收敛的研究状态：

```text
领域扫描
  → 候选 idea 池
  → 最近工作和冲突检索
  → 结构化辩论与审稿人攻击
  → 多维评分和致命门槛
  → 最低成本区分性实验
  → 用户明确选择
  → idea_contract.yaml
```

每个 serious idea（严肃候选）至少留下：问题和核心假设、机制与最强替代解释、最近工作和具体差异、新颖性与检索置信度、可杀死机制的结果、最便宜的区分性实验、审稿攻击及所需证据、主贡献和有证据基础的备选贡献。

使用者可以加入自己的领域见解，例如某类工作在自己的方向中通常不被认可、某个指标容易被质疑、某个基线实际上更强。这些见解应作为带来源和置信度的评估规则加入，而不是直接覆盖论文事实。这样系统会逐渐形成个人化的 idea 评估标准，同时保留可审计的证据链。

## 共享协议

跨技能文件统一保存在项目根目录：

```text
research_state.json
research_state/
├── ideas/<idea-id>/idea_contract.yaml
├── experiments/<experiment-id>/experiment_plan.json
├── experiments/<experiment-id>/verification_report.json
└── paper/claim_evidence.json
```

标准流转为：

```text
idea_contract.yaml
  → experiment_plan.json
  → verification_report.json
  → claim_evidence.json
  → paper_state.json
```

详细规则见 [`docs/shared-protocol.md`](docs/shared-protocol.md)，数据结构见 [`schemas/`](schemas)。

## 设计原则

- 三个技能通过文件协议连接，不通过隐式上下文连接。
- 每个技能只写自己拥有的状态目录。
- 想法机制发生实质变化时，实验计划必须失效并重新确认。
- 写作技能可以提出实验请求，但不能直接启动实验。
- 实验技能可以提出想法修订请求，但不能直接修改想法契约。
- 负结果、失败运行、缺失证据和阻塞项必须保留。
- 不允许把未验证结果写成论文结论。

## 安装

安装单个技能：

```powershell
python install-skill-from-github.py `
  --repo threeing3/research-agent-skills `
  --path skills/research-idea-lab
```

将路径替换为 `skills/research-experiment-lab` 或 `skills/ai-research-writing-skill` 即可安装其他技能。完整科研闭环需要安装三个技能。

## 诚实边界

这个项目可以减少读论文、搭故事和整理材料的负担，但不能保证 idea 新颖、实验成功或论文接收。它把论文看作一个需要管理不确定性的研究过程，而不是承诺结果的自动售货机。

## 兼容性

技能使用通用 `SKILL.md`（技能说明文件）格式，优先面向 Codex，也可迁移到其他支持 Agent Skills 的编程代理。
